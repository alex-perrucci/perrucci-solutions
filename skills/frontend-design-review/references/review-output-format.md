# Review Output Format

Use this structure for UI reviews.

## Frontend Design Review: [Component/Feature Name]

### Context
- Purpose
- Aesthetic direction
- User task

### Summary
Pass / Needs work / Blocked, with one-line assessment.

### Design System Compliance
Check component usage, tokens, variants, spacing and documented exceptions.

### Aesthetic Quality
Check conceptual direction, typography, palette, motion, composition and atmosphere.

### Pillar Assessment
Assess Frictionless, Quality Craft and Trustworthy as pass / needs attention / blocking.

### Design Critique
Give a verdict and rationale.

### Issues
Separate blocking, major and minor issues.

### Recommendations
Give specific component, token, typography, motion and implementation recommendations.
